# ptc-gate 对 ptc 的净价值探针 —— 门行到底被谁消费

> **本文职责**：回答唯一一个问题 —— **相对上游 `ptc`，ptc-gate 的门行是被消费过的功能，还是仪式**；
> 以及**怎么跑、跑完谁来判**。
> 机制与坑 → `docs/pitfalls.md`；门的回滚线 → `docs/decisions/0003`；价值腿与产出面读数 → `docs/decisions/0002`；
> 2026-09-30 那次优化（verbatim-gate + 语义层 ②③④）怎么测 → `docs/2026-09-30-ptc-gate-real-task-test-plan.md`
> ——**本文不重复它**。**本文只登记本探针自己的判据线**（先登记、后读数）；其余阈值一处都不复制。

## 0. 为什么这个问题还能问，以及这次的问法哪里不同

- ADR 0002 已经测过一次：三对配对 + 四层探针 ⇒ **两臂产出等价**（三次用户高判定的理由**全部落在过程面**）。
- `docs/2026-09-30-ptc-gate-real-task-test-plan.md` §6 把话说明白了：**persona / 门行的「效用」日志证不了**
  —— 文本被载入可证，「因此行为改变」不可由日志证明。
- ⇒ 所以本探针**不从日志证明效用**（那条路已被判定走不通），而是把效用**逼到日志外面**，只问一件事：

  > **门行有没有被任何人消费过？**

  这是**存在性**问题：否定答案自带处置（撤门行），肯定答案给 ADR 0002 的「产出等价」添一条反证。
  它比「产物有没有变好」便宜得多，也好判得多 —— 因为「有没有人依据门行改了主意」是个**看得见的事件**，
  不是一个要读几万字才能打分的质量判断。

## 1. 本探针能得出什么 / 得不出什么（先把话说死）

**能**：① 门行被消费的**实例**（0 或 ≥1）；② **税**（两臂每轮 token 的逐场并列读数）；
③ 同一次误读在两臂里**被发现时点的差**。

**不能**：比率、显著性、跨任务或跨模型的推广。**也拆不开 persona 与门行** —— A 臂比 B 臂多一个 orchestrator
persona，本探针量的是 **ptc-gate 整体 vs `ptc`**（这正是你问的那一句）。要拆开需要第三臂，见 §6。

## 2. 两臂与全部必须守住的常量

| 臂 | preset | 说明 |
|---|---|---|
| **A** | `ptc-gate`（本机现役那一个） | 有门行 + orchestrator persona + 看门狗插件 |
| **B** | `ptc`（上游自带那个） | 无门行、无该 persona —— **唯一被拿掉的就是这套纪律** |

**常量（任一条破了，本轮作废、不可解读）**：

1. **同一个工作区**跑两臂（否则 reader 读不到同一批会话）；
2. **同一个任务原文**（两臂一字不改地贴同一条 prompt）；
3. **同一条模型路由**（两臂不得换 provider / model）；
4. **不在本 preset 自己的仓库里做** —— 自指会污染（agent 能读到门插件的源码，这正是 ADR 0002 的窗口条件「非自身仓库真实任务」的由来）；
5. **两臂都由你亲自当用户**，且**只按 §4 的方式干预**。

## 3. 任务怎么造：一个「代价不对称的可判歧义」

**这不是随机挑活**：任务必须在跑之前就写清两种合法读法，且代价相差 ≥3 倍。

| 记什么 | 内容 |
|---|---|
| **R1（便宜读法）** | 字面完成、代价小、**看起来也对** |
| **R2（昂贵读法）** | **你真正要的**那个，代价大得多 |
| 为什么两者都合法 | 一句话 —— 说不出来就换任务 |

**推荐的形状：根因修复 vs 调用点补丁。** 「某个行为在某个场景下不对，修一下」——字面上「修一下」完全成立，
而 R1（在出问题那个调用点加特例）与 R2（在公共层修根因、所有调用点一起好）都是正当工程选择，代价差常在 5 倍以上。
门行如果真有用，它该在这条歧义上拦住你 —— 这是门**唯一**声称的价值：**在第一次动手之前**把读法摆出来。

**挑选清单（全部满足才能用）**：

- 是你**本来就想要**的活（ADR 0002 的窗口条件：真实任务，不自造需求）；
- 能在一场会话内做完，且**结果可判**（做完你能说清对不对）；
- R1/R2 **都合法**，且你能预先指出「R2 才是我要的」；
- 任务原文里**不出现**任何指向 R2 的暗示（否则测的是你的提示词，不是门）。

**可直接采用的 prompt 模板**（把方括号替换成你的真实内容）：

> `[仓库/模块]` 在 `[场景]` 下行为不对（复现：`[步骤]`）。修好它。

配一条**预先写死**的 R1/R2（例）：

| | 读法 | 代价 |
|---|---|---|
| R1 | 只在 `[出问题的那个调用点]` 加一个特例 | 改 1 处 |
| R2 | 在 `[公共层]` 修根因，`[所有调用点]` 一起受益 | 改 N 处 + 回归 |

## 4. 你要记录的四件事（只有一件是人的判断）

| # | 记什么 | 何时记 |
|---|---|---|
| **L1** | A 臂的**门行原文**（`Intent: …` 那一整行） | 它一出现就抄下来 |
| **L2** | 你**在第几条消息**发现它读错了（A 臂可能是门行阶段，B 臂通常晚得多） | 发现的当下 |
| **L3** | 那次纠正**避免了什么**（一句话；若其实没避免，就写没有） | 纠正后立刻 |
| **L4** | 任务结束后写**三条判定理由**，标明落在**过程面**还是**产物面**（照 ADR 0002 的口径） | 结算时 |

> ⚠️ **L3 是本探针唯一的人判断，也是唯一可能自欺的一格**：写「避免了返工」时，问自己一句
「如果门行没出现，我会在哪一步才发现？」。答不上来就写「没有避免」。

## 5. 判据（跑之前定死，跑完不许改）

- **仪式假设存活**：全部 A 臂会话的 **M1 合计 = 0**（门行从未被任何人消费）⇒ 门行的唯一消费者是闸门自己；
  处置 = 提一条**撤门行**（或降为可选）的提案，按 §8 落纸。
- **仪式假设被证伪**：**M1 ≥ 1 且 L3 属实** ⇒ 门行至少有一次真实功能，写进 ADR 0002 的后续段。
- **M1 = 门行发出之后、首次动手之前，你依据门行做出纠偏或明确确认的事件数**。
  它必须发生在**门行那一条消息之后、该轮第一个行为动作之前** —— 否则记 0（那是普通交互，不是门行起的作用）。
- **税**：两臂每轮 token 差，逐场并列报出，**只报数、不设线**。
  ⚠️ **你对税的容忍度必须在看到 M1 之前写下来** —— 否则你会用「反正它有用」把它合理化，或用「反正它没用」把它夸大。
- **阴性对照（必做）**：一场**零歧义**任务（明确到没有第二种读法）× 两臂。若 A 臂在这场也报出 M1
  ⇒ **M1 判据在空转**（把普通交互记成了门行的功劳）⇒ 整轮作废、重设判据，不许拿它还嘴。

## 6. 跑法（阶梯；不必一次跑完）

**第 0 阶 · 协议自检**：零歧义任务 × 2 臂。目的不是结论，是证明 §4 的四格你填得下来、reader 读得出这两场。

**第 1 阶 · 主测**：**≥2 对**（同一任务 × 两臂 = 4 场），**顺序对调**（第 1 对先 A 后 B，第 2 对先 B 后 A）
—— 对调是为了把「第二遍更熟」的学习效应对冲掉。

**可选第 2 阶 · 第三臂**：`ptc` + **只挂门插件**（不带 orchestrator persona），用来把「persona 的功劳」与
「门行的功劳」拆开。代价：要改一行 composition 并做**一次真正的重新挂载**；本探针的主问题不依赖它。

**每场开场前**：按 §3 把 R1/R2 写进本文的登记位；**开场后**：A 臂只在门行阶段纠偏，B 臂按你平时的习惯（发现才说）。

## 7. 跑完怎么读（判的人是我，但读数只能出自唯一 reader）

```bash
cd /Users/eric/Project/tests/dsh-plugins/cireric-dsh-ptc-roles
node scripts/verify-ptc-roles.cjs --cwd <两臂共用的那个工作区> --raw
```

我要的字段：**逐场**的 preset 身份、`system/message` 载入代次、token 四桶、轮数与行为轮数、闸门拒绝账；
再配上你 §4 的四格记录。**我不会用**：我自己对你叙述的转述、临时 grep 出来的数字（AGENTS.md 规则 9 / pitfalls #24）。

⚠️ **先确认不是空跑**：输出里必须有 `会话 N 个（工作区 …）` 且路径就是那个工作区 —— `--cwd` 写错时 reader 会退 0、
看起来一切正常（那份 2026-09-30 的计划记过这个坑，别再踩一次）。

**税只逐场并列读，不做跨会话汇总**（pitfalls #22③：seeded 子会话是父事件的深拷贝，相加会算两遍）。

## 9. 本文故意不覆盖 / 已知边界

- **比率与显著性**：n 只有 2–3 对，本探针给不了；那是 ADR 0002 那种配对法的活。
- **persona 与门行的拆分**：主测只有两臂，拆不开（可选第 2 阶）。
- **`LATE` 拒绝支 / win32 平台分支 / `run_code` 里的 Node 直写**：各自的登记处见那份 2026-09-30 的计划 §6。
- **模型的内部动机**：门行有没有让它自己改道，日志里读不出来 —— 所以 M1 只认**你**的动作。这是本探针最硬的一条边界，不是缺口。
