# ADR 0004 — 语义层借鉴三件（ideal-state / 成本公理 / 假设复核）与试点判定线

- 日期：2026-09-30
- 状态：**已采纳**（用户 2026-09-30 确认 grill 十题 Q1–Q11 全按推荐 + 可行性分析）

  —— 机制层借鉴① verbatim-gate 归彼处，本文只管语义层）/ `docs/pitfalls.md` #16（内容质量机械不可见）/
  #19（合规率是机制健康检查，不是成绩）/#22（预登记纪律）/ #24（临时探针不进结论）
- 出处：code-yeongyu/oh-my-openagent 意图门工作流对照分析（2026-09-30 会话，源码实读 dev 分支）；
  借思想不借载体——四项里交互访谈协议、跨会话 stance 记忆、plan 工件体系、巨型规则体**明确不借**
  （机制错位：DSH 无阻塞提问 / preset 无自有跨会话存储 / 违背 ADR 0002 净删方向）。

## 背景

ADR 0002 窗口读数的未解症状：三次用户高判定的理由**全部落在过程面**（「能正确派遣 librarian」「识别需求
正确」「完成快」），两臂产出等价——编排纪律对齐了「过程正确」，没对齐「产物价值」。OmO 的
affected-user + ideal-state rows + gap 账本是冲着同一问题设计的机制；本仓取其内核、按 Q11=B 降为
reply 侧一句话。

## 决定

1. **② ideal-state 一句话（reply 侧，门行契约不动）**：persona 要求行为轮的 reply 含一句受影响者说明
   （「这改的是谁的什么」，措辞指向**具体的、若被忽视会受损失的人或程序**——OmO 隐性用户清单是素材：
   读日志的运维、调 API 的下游程序、消费产物的另一个 agent）。落点 = reply 独立一句，**不扩门行模板**
   （D 契约三读者零改动）；理由：①（ADR 0003 追加）刚收紧门行机械面，同迭代再动模板会让回归不可归因。
   定位 = **未验证假设**，试点后才谈固化。
2. **③ prompt 三件套**（零机制增量）：
   - **不对称公理成文**：「错杀用户发言权 > 多问一句；不必要的问题失败得便宜响亮，错误默认失败得昂贵
     隐形」——强化既有「otherwise take the option you judge best」，给模糊地带一个显式裁决序；
   - **fence 自曝宣告**：意图落在模糊地带时在门行内显式自曝（「这条我按 X 读的，错了纠正我」），
     把误判纠正成本压到用户一行回复；
   - **对比方案默认先行**（OmO examples-first 的单轮退化形态）：真 fork 幸存且证据无法裁决时，reply 给
     2-3 个带推荐默认的对比方案——**仅此条件**，没有 fork 不挂（防每条 reply 都挂三方案的噪音）。
3. **④ MUST-VERIFY（假设复核交接，窄范围）**：orchestrator 在**无用户确认**下采了**会改变验收结果**的
   默认且该轮发生委派 ⇒ 该假设进委派 brief（五件套内一行，不违反「never forward the whole contract」），
   由子代理按 NEEDS_CONTEXT 惯例复核（语义已在位：假设改变验收 ⇒ 上报）。**边界承认**：四判据 + 实测
   2.4–6.4× token ⇒ 委派在 ptc-gate 是小概率事件，④在此是边角机制（验证形状，不产生规模价值）；其主场
   在 ptc-roles（oracle/reviewer 现成），验证有效后按 Q1=A 回移植。闭环承诺 = **错误显形**，不承诺自动修复。
4. **persona 预算（Q6=A）**：②+③+④ 合计净增 ≤5 行；既有 anti-parroting 与 anti-bookkeeping 两句合并腾位
   （同一主题两面：「读者是用户，别照抄、别记账」）。合并后语义受损 ⇒ **弃④保②**（②连着价值问题，
   ④在 ptc-gate 本是边角）。

## 预登记判定线（先登记、后读数；不接退出码——同 #19/#22 纪律）

- **试点形态（Q10=A）**：前 2 场真实任务喂线，②④同场观察，**不专门造任务**；②只计**交付型任务**
  （纯调查类无产物，不触发不记失败）。窗口启动器 = ADR 0002 的「非自身仓库真实任务」条件不变。
- **② 固化/放弃**：固化线 = 2 场内用户判定理由 ≥1 次落在**产物面**（基线 = ADR 0002 三次全过程面好评）；
  **0/2 ⇒ 弃**（撤 persona 句，登记一条 failure record）。
- **④ 保留/放弃**：保留线 = 成本 ≈ 0（brief 多一行，无额外 token 量级）即保留；放弃线 = 3 场内 0 抓获
  **且** reply 明显变长。读数歧义防呆：区分「没触发」（无委派轮）与「触发了没抓到」——探针级区分落
  `.tmp/` 标未复核（#24），不进 `docs/`。
- **③ 验收**：行为观察（fence 自曝出现次数），无机械证据也不可能有（#16）；无独立回滚条件（删行即回滚）。
- **②固化后的回移植**（Q1=A 预留路径）：persona 句 + 试点读数一并进 `ptc-roles` 的 persona 批次；
  回移植本身再走一轮 ADR 追加，不在本文预支。

## 否决过的选项

- **②走门行模板扩写**（`（为谁：<受影响者>）` 进模板）：契约变更三读者同步、每条门行变长，且与①同迭代
  叠加判据漂移风险 ⇒ **本轮否决**；试点有效且需要更强可见性时可升级（顺序：B→A 可，反向不划算）。
- **②④建 Open-assumptions 账本 / plan 工件**：OmO 载体依赖其 .omo/ 目录体系，本仓无此形态且 ADR 0002
  已裁定净删方向 ⇒ 账本降级为 reply 内假设清单，**否决**。
- **④全量假设进 brief**：每条 brief 挂假设清单 = 噪音，违背五件套纪律 ⇒ 限定「改变验收结果的默认」，**否决**。

## 后果

- persona 批次（②③④）一次编辑、一次 `make verify` / `make control`；与 ADR 0003 追加段的机制改动
  **分两个提交面**（机制 vs persona），回归可归因。
- 判定线读数由 reader 打印承接；reader 现无「产物面/过程面判定理由」的自动读数（判定理由是人的输入，
  机械不可得）⇒ 该线靠用户任务后自评记录，落证据文件（`docs/evidence/` 惯例），**不接退出码**。
- 本文不复制口径：门行判据见 #19 与 ADR 0003 追加段；NEEDS_CONTEXT 语义见本仓实测记录（2026-09-24）。
