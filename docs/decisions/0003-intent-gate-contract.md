# ADR 0003 — 意图门的契约与回滚条件

- 日期：2026-09-21
- 状态：**已采纳**（用户 2026-09-21 逐条确认 grill 轮的 Q3–Q14）
- 前置阅读：`docs/pitfalls.md` #19（口径）/ #20（可强制点）/ #23（读法）；本文只回答**为什么这样定、
  否决过什么、什么时候回滚** —— **口径不在这里复制第二份**。

## 背景

门的契约此前散在三处：persona（规则）、插件（提醒与拒绝的文案）、`HANDOFF.md`（开闸前置与回滚条件）。
而 `HANDOFF.md` 在本仓是**临时交接件**（可整份重写、无人引用）⇒ 把安全阀放在会被重写的文件里，
等于没有安全阀。

## 决定

1. **一个口径，三个读者**：persona 的模板、插件的提醒 / 拒绝、reader 的合规分子共用同一个判据
   （① 存在：门行位于承载首个行为动作的那条消息、且为该消息首行）。口径的唯一登记处是
   `pitfalls.md` #19；三处漂移由 `verify-intent-gate-watchdog.cjs` 的契约一致性（D）与
   `verify-ptc-roles.cjs` 的断言钉住。
2. **闸门是「行为纠正」，不是「位置警察」**：`enforce` 下每轮最多拒一次，判据是「本轮出现过门行」
   （实现上 `declSeq <= carrier`，而 `carrier` 取「最后一条 assistant 消息」的序号 ⇒ 只要声明被记上
   就一定成立）。它**不**强制 ① 的位置：被拒后补行重发的轮次在 ① 口径下仍记 ✗（#19 的读法注记）。
   这是有意的 —— ① 是度量，闸门是纠偏，两者可以同时为真。推论：拒绝理由里「门行晚了」那一支
   **今天不可达**（`declSeq` 一旦被记上就必然 `<= carrier`），它保留为状态真变化时的正确文案，
   单测只钉可达的那一支。
3. **模式进数据面**：`config.gate` 写错会静默落到 observe（fail-safe），而本部署没有日志通道（#9）
   ⇒ 插件每**会话**注入一行 `[intent-gate-watchdog] mode=enforce|observe`；reader 拿它与
   `preset/<id>/preset.patch.yml` 的**声明**对照（0.2.0 前的文件名 `agent.cordis.yml`），不一致 ⇒ ✗ FAIL（缺席只作观察：本会话可能挂载于
   标记引入之前，判据见 #A 节的「重新挂载」）。
4. **回滚条件（唯一登记处 = 本文）**：观察期判据曾是「注入通道里出现过 `RACE_REPORT`」，但 enforce
   之后 `wouldDeny && !denied` 恒不成立 ⇒ 那条报告**永不注入**。改判为它的镜像：
   **假拒候选 = 被拒过的轮最终仍判 ① 合规**（插件注入 `FALSE_DENY`；reader 从**既有事件**独立算出
   同一个数，打印为 `闸门拒绝: … ｜ 假拒候选 n`）。**读到 n > 0 ⇒ 改回 `observe`**，并在确认
   「有没有一次真正的重新挂载」（#A 节）之后重跑。

## 否决过的选项

- **proactive 提醒**（每轮开轮时先注入一行，替代「被拒 → 补行 → 重发」的往返）：代价是每轮永久落库一行
  （#19 的 7 行 → 3 行教训），而拒绝实测很少（本场 1 次 / 3 轮）⇒ **否决**。
- **把闸门收紧到 ① 的位置**（用该次调用真正的载体，而不是「最后一条消息」）：会让「先只读侦察、补行、
  再动手」这种合规形态被拒；且 #17 的载体耦合已被判为**口径产物**而非模型漏行 ⇒ **否决**。
- **用正则判「模型是无视还是没看见」**：内容质量不可从数据面机械判定，误伤面更大 ⇒ **否决**
  （同 #16 的取舍：内容质量只能靠 prompt 侧）。
- **把「被拒后仍无门行继续」做成注入记录**：该事实已完全可从**既有事件**推出（拒绝 seq + 同轮后续
  事件）⇒ 交给 reader 的读数，不新增永久落库的消息。Q3② 据此换了实现方式，**判据不变**。

## 后果

- 改插件文案要**同时**改 persona 与单测（D 契约 + 集合相等的阴性对照）；改完 `.mjs` 必须
  `dev_reload_preset` **且**发生一次真正的重新挂载（#A 节）。
- `make verify` / `make control` 是这条契约的唯一回归面；`make check` 只管部署形态（未部署 = ⓘ）。
- 本 ADR 引用的读数每次都要带「口径 + 窗口 + 日期」；口径本身仍在 #19，别在此处复制。

## 2026-09-23 追加（第二轮：预登记线的分母，与两处前提更正）

1. **预登记弱线的分母定死，并且搬到这里**（此前散在 `HANDOFF.md` 与 0002 的改判段**两处** —— 前者正是本文
   背景段说的「把安全阀放在会被重写的文件里，等于没有安全阀」，原地不动是自相矛盾；两处现已全部改成指针）：
   **拒绝率 = 被拒的 user-opened 行为轮 ÷ user-opened 且会改变行为的轮**（与现役合规分子同分母；
   reader 逐场打印 `闸门账: … ｜ 拒绝率（user-opened 行为轮口径）`，口径登记处仍是 `docs/pitfalls.md` #19）。
   **弱线：单场 >0.5，或连续两场 0 恢复 ⇒ 复审**（不接退出码，判据见 §4 的回滚条件）。
   [窗口 = 本仓库工作区，2026-09-23 当场：`session-299709d6` **1/1 = 100% ⇒ 越线**；同场旧「每轮制行为轮」
   口径是 1/3。**越线不是门的故障**：那场唯一的拒绝落在只读侦察上、恢复 1/1 —— 它量出来的是「开轮就动手」。
   读数已留档：**证据 ⑱** `docs/evidence/2026-09-23-gate-deny-account.json`（`--snapshot` 原样输出）。]
2. **两处前提更正**（先前的推断被代码阅读证伪，登记在此以免再被引用）：
   · **「并发导致多拒」不成立**：插件的 latch（`wouldDeny = true` → `if (denied) return` → `denied = true`）
     是**同一个同步块**、中间没有 `await` ⇒ 同轮并发两个行为调用也只可能被拒一次。单测已加一条并发断言钉住
     （`verify-intent-gate-watchdog.cjs`，阴性对照集合同步扩了一条）。
   · **「同一 program 的后续派发会被拦住」不成立**：闸门每轮只拒一次（本文 §2 的有意设计），被拒 program 的
     其余派发**照跑** —— 窗口内实测那把 program 共 6 次派发，其余 5 次全部执行。reader 现在把这个事实读出来。
3. **闸门是路径级卡点，不是能力边界**：`tools.*` 之外的 Node API 直写既不过门、也不进合规分母 ⇒ 门与度量
   共享同一个盲区。事实、范围（0.1.5-rc.2 vs ≥0.1.6）与「不写正则 linter」的取舍见 `docs/pitfalls.md` #28；
   persona 已补一条 prompt 侧防线。

## 2026-09-30 追加（第三轮：verbatim-gate —— 六桶的机械校验，来自 OmO 对照分析）

> 决策上下文：`/grill-me` 十题（Q1–Q6 需求轮 + Q7/Q8/10/11 落点轮）全部按推荐锁定；可行性分析确认后采纳。
> 需求裁决：目标 preset = `ptc-gate`（验证有效后回移植 `ptc-roles`）；误拒容忍 = 低（deny + 恢复路径 +
> FALSE_DENY tripwire，机制现成）；正则形态 = 桶词 + 词边界（Q7=A）。

1. **判据收紧：marker 检查从「子串」升级为「桶词 + 词边界」。**
   现状（[源码] 2026-09-30 核实）：插件 `intent-gate-watchdog.mjs`（`text.split('\n')[0].includes(marker)`）
   与 reader `verify-ptc-roles.cjs:689`（`hasFirstLineMarker`）**两处均为子串匹配**，`Intent: 随便` 双双过闸
   —— 六桶枚举只是 REMINDER 文案里的 prompt 侧请求。收紧为：
   `/^Intent:\s*(research|implementation|investigation|evaluation|fix|open-ended)\b/i`。
   **边界（同 #16 的取舍，不推翻）**：分隔符 `—`、`because:/依据:` 从句、commitment 结构**一律不校验**
   —— 机械层只管「桶是不是六个之一」，内容质量仍只住 prompt 侧；任何「连分隔符/从句也校验」的提议都是
   向内容 linter 滑坡，属本文第二轮已否决的同类。case-insensitive 压误拒（对齐 OmO `/i` 惯例）。
2. **拒绝理由三态化**：桶无效被拒时模型是「写了但写错」，不能沿用 MISSING 文案（那瞄准的是「根本没写」，
   #19 的教训：纠正话术要瞄准真实犯的错）⇒ 新增 `GATE_REASON_INVALID`：列出六个合法桶 + 补行话术。
   三态 = MISSING（没写）/ INVALID（写了但桶不合法）/ LATE（按 §2 今天不可达，文案保留不删）。
   **拒绝账按理由分桶打印**（MISSING/INVALID 计数分开），否则三种错误混在一个数里不可归因。
   reader 拒绝账的成对判据（`[intent-gate]` 前缀 + 行为工具名）不变，理由分类按结果文本再分。
3. **reader 分子不动，严格读数并列新增**：合规分子（宽松子串）**保持原样** —— 口径历史可比性是命根子
   （#19 整节在收拾口径漂移的残局），本轮不再断一次口径链。新增一行「严格合规 n/m」对照读数，且**只对
   带 mode 标记的会话计算**（旧 token 时代会话严格读数恒 0，混算即复刻 #19 的「跨代次不可汇总」故障）。
   宽严差是有意的：deny 是行为纠正、分子是机制健康检查（§2 已确立两者可同时为真）；口径差异登记进
   `pitfalls.md` #19，不在此复制。
4. **同步面四处**（改一处漏三处 = 本仓 #12 类故障）：插件 marker 正则 / reader 严格读数 / 单测（D 契约 +
   阴性对照集合相等）/ fixture（新增「桶无效」夹具：`Intent: 任意词` 必须被拒 + INVALID 文案断言）。
   假拒线**不受污染**：补行重发的轮次按现行读法记 `✗[动后补]`，`denied && ①合规` 不成立 ⇒ FALSE_DENY
   不触发 —— 已核对插件 latch 与 reader 判据（[源码]）。
5. **回滚条件沿用 §4 不新增**：假拒候选 n > 0 ⇒ 改回 observe；弱线（单场拒绝率 >0.5 或连续两场 0 恢复）
   ⇒ 复审。桶校验的误拒（中文桶名、拼写错）落进同一套既有回滚线，**不新设阈值**（#22 的「不新定阈值」纪律）。
6. **出处**：机制对标 code-yeongyu/oh-my-openagent 的 IntentGate（`z.enum` 封闭桶集合 + 按实质不按措辞的
   决定表，[源码] dev 分支）；本仓缺口由 2026-09-30 源码核实（插件 `rec.declSeq` 记录条件 + reader
   `hasFirstLineMarker`）确认。 OmO 机械层的其余部分（注入后撒手、无强制、无 reader）**不做对标**：
   ptc-gate 的 pre-execute 闸门 + 数据面 reader 在机械层强于 OmO，反向无借鉴项。
7. **实现裁决回写（同日施工轮，评审发现两点 §2/§4 未定义或前提有误，登记在此）：**
   · **假拒候选判据改按严格① —— 这是对 §4 回滚线判据的实质改判（本条即登记处）。** §4 原文
     「已核对插件 latch 与 reader 判据」只覆盖了**补行重发**形状（门行在被拒后出现 ⇒ ① 不合规）；
     **桶无效**形状下宽松 declSeq 会被 `Intent: 任意词` 的首行**抢先记上** ⇒ `denied && ①宽松合规`
     在**第一个合法的 INVALID 拒绝**上就成立 ⇒ 误触「假拒候选 n>0 ⇒ 改回 observe」。裁定：reader 的
     恢复 / 无门行继续 / 假拒候选三项一律换**严格 declSeq**（与插件 compliant() 同源）；口径登记进
     `pitfalls.md` #19（2026-09-30 追加段），fixture 以桶无效 case 的 `falseDeny: 0` 钉住。插件侧
     无需改动即自洽（其 compliant() 本就以严格 declSeq 为准）。
   · **MISSING/INVALID 的分界 = 首行**：gateish 判别只认**首行** `^Intent:` —— 门行不在首行（桶本身
     合法）归 MISSING（位置错属「没写到点上」），不误用「桶不合法」文案；单测 33 钉住。
8. **副本同步的登记（回应「目标 preset = ptc-gate」与组成契约的张力）**：组成契约
   （`deploy-preset.cjs --compose`）强制两份门插件**逐字一致** ⇒ 机制改动必须同时落 ptc-roles 副本；
   §需求裁决的「目标 preset = ptc-gate」指的是**验证窗口**（启用中的 preset 的会话读数），不是文件落点。

   `agent/turn-stopping` 在 **PTC** 会话里的触发已核实（今只核到钩子存在、可 `agent.steer(...)` 让机器
   再跑一步，未核 PTC 一致性）。
5. **R1 否决：断言对象不在本仓管辖内。** 三类 finding 指向的对象（裸 `fs-local` 后端 / `fs` 服务挂载 /
   破坏性守卫）按 preset 自己的注释都住在 **host composition**（`preset.patch.yml`：sandbox 与 approval

   「否决 sandbox-strip 的理由。**先有失败记录再谈**」，另见同类结案「不是缺口……保持检测」）。
   **反转触发**：出现一条**本仓行自身**的实测失败（如引号规则那类静默产出非字符串 allow 项的故障
   复发）⇒ 以「本仓行的静态断言」形态复活；那是一条新需求，不是本文的 R1。

10. **复核轮：R-A 形态改判 · 判死线落数 · §4② 定语修正**（2026-10-01 第二场，三条都由**静态矛盾**
    触发、不靠新数据；口径本体在 `pitfalls.md` #19，本文不复制）：
    · **形态改判（§3 的「两行读数」→ 六桶 × 动作类别母表）**。判据 = §3 自称要回答的问题「门行有没有
      信息量」，其字面定义是**条件分布是否随桶改变**；两行计数让 `fix` / `implementation` 两桶恒不可见、
      并把六桶压成两个数 ⇒ 违反本追加段第三项自己立的「混在一个数里不可归因」。**两行保留为派生值**，
      不得充当判据载体（「筛查通过 ⇒ 有信息量」是错误推理）。现场证据：唯一 reader 当场读出本工作区
      3 场带 mode 标记会话 / 16 个行为轮 / 15 轮桶合法，而 reader **一行桶分布都打不出来**。
    · **判死线落数（§3 的「桶集中在 `open-ended`」）**。原句是形容词，与本段其余线（弱线 >0.5、
      假拒 n>0、ADR 0004 ② 0/2）不同构；形容词线在读数之后可移动 ⇒ 预登记失效。定为两条 ——
      **① 上限**：窗口内行为轮的门行桶中 `open-ended` 占比 **≥ 1/2** ⇒ 命中（重审六桶契约，乃至撤销门行）；
      **② 下限**：行为轮数 **n ≥ 2 × 桶数 = 12** 才允许出现判死结论，`n < 12` 时该读数只作**第 0 阶
      协议自检**（证明母表填得下来、两处正则同源）。**窗口** = 判定时点本工作区全部**带 mode 标记**的
      会话（同 §3 严格对照的口径：旧 token 时代不并入）。两数是推导值不是选择：1/2 = 「集中」的最小读法，
      12 = 「每桶平均 ≥2 个样本」的下界。[当场：n = 16 ≥ 12 ⇒ 第一场读数即可判死。]
    · **§4② 定语修正**：原文「R-A 的矛盾读数**证明判据可用**」把一行被 #19 明写成「不进任何阈值判定」的
      观察读数写成了门槛 ⇒ 该项自本条起重述为「R-A 的母表**逐格复核**过 closure 判据（只读桶 ×
      `write` / `edit`）的假阳性面 —— **定性复核，不设阈值**」。用途不变，登记面不再自相矛盾。
    · **用途收窄（预登记，先于读数）**：本条**只登记证伪方向** —— `open-ended` 占比命中 ⇒ 判死。
      母表**不能**用来证明「门行有信息量」：桶分散 + 各桶动作分布无差异是**另一条**信息量为零的路径，
      而本条没有给它登记任何判据 ⇒ 出现那个形状时**当场无判据**，必须另开一条预登记线再裁决
      （不许把「六行看起来不一样」当场读成结论）。**同日已补上该线：见本段第 11 项。**

    · **施工顺序（固定）**：① 本段 + `pitfalls.md` #19 落口径 → ② reader 母表 → ③ 第 0 阶读数；
      三步全免重挂载（同 §8）。**未登记前不得读数** —— 数据已在盘上（16 轮），先读后定即事后归因。
11. **R-A 第二条线：桶间「动作分布无差异」（预登记）**。起因 = 第 10 项的首次读数**落在「无判据」格**：
    桶没塌（`open-ended` 1/19 = 5%），但 `investigation`(0/5, 0/5, 5/5) 与 `evaluation`(0/3, 0/3, 3/3) 的
    **动作命中率三元组精确相等** ⇒ 这两个桶在动作面上不可区分（口径在 `pitfalls.md` #19，本文不复述）。
    · **判据（命中）**：存在两个桶，**各自 n ≥ 2**，且三元组**精确相等**（有理数相等，无容差、无统计检验）。
    · **后果（命中）**：**重审该组** —— 合并为一个桶，或删掉组内至少一个桶；**不**触及门行本身的存废
      （那是第 10 项第一条线的事）、不自动改任何东西、不接退出码。
    · **为什么是「精确相等 + 每行 n ≥ 2」**：两个数都是**推导值不是选择** —— 「分布无差异」的字面读法就是
      率相等（容差 = 自造阈值）；一行只有 1 个样本时它和任何一行都「相等」，那是样本不足、不是无差异。
      代价有意接受：它只作**下界/证伪**，率略有差异的真退化会被漏掉（宁漏不误判）。
    · **不新增阈值**：命中不需要数量线（n ≥ 2 是「分布」一词的最小样本要求，不是判定阈值），后果也只是复审。
12. **R-A 重审该组：两条轴的预登记（第 11 项命中后的下一步）**。第 11 项命中后要回答的是「桶真的不可
    区分，还是我的观测面太粗」⇒ 补两条**名字/参数级**的轴（定义与边界口径在 `pitfalls.md` #19，本文不复述）：

      （`.tmp/` 是 AGENTS.md 规则 9 的探针例外 ⇒ 不算产出；这同时是矛盾计数现行口径的**已知假阳性面**。）
    · **问人轴**：该轮是否出现 `ask_user_question`（persona 对 evaluation 的定义是「提议 → 等确认」）。
    · **判据（三态）**：组内成员在**任一条轴**上的命中率**不精确相等** ⇒ **可分** ⇒ 结论是**观测面太粗**，
      桶不必合并；两条轴都有变化而率精确相等 ⇒ **不可分** ⇒ **这才够格谈合并**（即第 11 项的后果）；
      两条轴**两边都是 0** ⇒ **无结论** —— 零变化率的「相等」不是证据，一条从未观测到的轴分不开任何东西
      （第三态是 2026-10-01 首读当场补的：当时窗口里两桶两条轴全为 0，按原判据会被读成「够格合并」）。
    · **参数缺失记「未知」，不记 0**：`file_path` 读不到 / 工作区根未知 ⇒ 进 `参数未知` 计数并打印 ——
      否则一次字段改名就能把结论翻面而无人知晓（本条登记的起因正是我先断言「PTC 拿不到参数」后自查推翻）。
    · **本轮否决的第三轴（外部来源）**：它要靠一张手工工具名清单（`mcp__lsp__*` 是本地的），漏名 =
      静默少算，与 #12 的副本病同族。**也不解析 `bash` 的命令文本**（内容 linter，#16 的边界不推翻）。
    · **可分判定自身不需要阈值**（率相等是精确有理数比较）；但「无结论」必须**到期**，否则这个组永远悬着 ⇒
      **到期判据（登记如下；它与第 10 项的 `n ≥ 12` 是两个不同的数，含义不可互换）**：
      **X = 36** —— 口径 = **该组自己的行为轮数**（成员桶的 n 之和，**不是**全窗口 n：两轴的变化只会发生在
      这两个桶里，拿别的桶的样本量来给这组的结论背书是错的）。该组轮数 ≥ 36 而两条轴仍全 0 ⇒ 判
      「**两轴对该组不适用**」并**结案**：不合并该组 + 登记 R-A 在动作面上的能力上限。
      推导：`⌈ln(0.05) / ln(0.9)⌉ = 29`（轴的**真实**发生率哪怕低到 10%，也需 29 轮才把「一次都没观测到」

      低于名义值，故取保守侧。代价不对称：悬置成本 ≈ 0（无人依赖它做决定），**错结案的成本是结论固化**。
    · **不接退出码**：「可分」与「不适用」都不是判决，而是给第 11 项的后果换输入。
