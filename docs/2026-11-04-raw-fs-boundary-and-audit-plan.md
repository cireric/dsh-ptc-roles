## 2. 否决理由（四条）

### 2.1 没有失败记录（`AGENTS.md` 的规则演进原则）

「解决过实际失败才设规则」。原计划没有任何现场：既没有一次「模型用 raw fs 写了工作区文件」的记录，
也没有一次「模型因为怕规则而绕路」的记录。裁决当时读数（**2026-11-04，窗口 = 本机滚动会话库，
命令见 §6**）：主 agent 会话 25 场 / 程序 661 个 / 含 fs 写方法名 **0** / 参数读不出 2。
⇒ 盲区是真的（#28），但**没有被用过**。

### 2.2 例外表不可执行（规则自指）

Appendix A 允许「写 `git check-ignore` 命中的构建产物」，但判「是否 ignored」只能跑 git：要么
raw `child_process`（这条规则本身禁止），要么 `tools.bash`（行为轮、要门行）。**判定路径的手段
自己受这条规则约束** ⇒ 模型只能猜，产出灰区而不是边界。

### 2.3 效果审计测不到它声称的东西

`git status` 是**现在**，`toolWriteEvents` 是**历史上某场会话**。对账要求「干净基线」，
而本仓工作树裁决当天就是脏的。把「先 commit / stash 再审计」写进流程，等于用**动用户工作树**
换一个仍然无法归因的数字。

### 2.4 与已采纳决策冲突，且本批不推翻

[`pitfalls.md`](pitfalls.md) #28② 与 [ADR 0003](decisions/0003-intent-gate-contract.md) §3 已登记：
**「不要写正则 linter 去判程序文本里有没有 fs」**（理由：误判面大于收益；同 #16 的取舍）。
原计划全文没有引用这两处。推翻它需要**新证据**（一次真阳性 + 误报率），不是一份新计划。

## 3. 唯一落地物：reader 里的 `raw-fs 观测`

位置：`scripts/verify-ptc-roles.cjs`（`analyze()` 采集 + 逐场/合计两行 + 7 条自测断言）。

口径（**上界**读数，不是违规计数）：

- `程序 N 个` —— 本场 `run_code` 的 `tool/call` 数（`code` 在 `arguments` 的 JSON 串里，原生形状）；
  采集**不放在 turn 守卫里**：少一个 `turn` 字段就会让整段程序从观测里消失。
- `含 fs 写方法名 K 个` —— 程序文本里出现**写调用形状**（成员调用或解构后的裸名调用，
  如 `.writeFile(` / `writeFile(`）；注释 / 字符串 / 模板 / 正则字面量里的同名文本不计。
- `参数读不出 U` —— `arguments` 解析不出 `code` 的程序数，单独计数，**不按 0 算**。
- 不判路径、不判 tracked/ignored、不判违规、不接退出码；逐场只在 `K>0` 或 `U>0` 时打印，
  合计行恒打。

已知偏差（写在这里，阻止后来人把它当精确值）：

- **少算**：`const w = fs.writeFile` 这类别名赋值、模板插值里的真调用。
- **多算**：`/` 当正则的启发式（前一个字符是 `=` `(` `,` 之类才当正则），在除法/哈希上会判错。

自测的「牙」由内存变异对照证明：去掉 mask ⇒ 字符串 / 注释 / 模板 / 正则 4 条转红；
去掉裸名匹配 ⇒ 解构调用 1 条转红（不改文件，跑一次即验）。

## 4. 什么条件下重开

满足任一条再谈机制，且**先写误报率与误伤代价**（#16 / #28 的判据），不要先写计划：

1. `raw-fs 观测` 的 `含 fs 写方法名` **出现非零**，且人工复核确认是**写工作区文件**（不是字符串/正则误报）。
2. 出现一次可指的现场：某场会话、某条路径、谁发现的（agent / 用户 / 事后审计）。
3. 运行时侧能给出「按会话切的工作树快照」—— 效果审计的归因前提，现在没有。
